HASKINS INDUSTRIAL COMPLEX
Website and API audit — developer checklist

Use this checklist to approve scope before implementation. Mark each item
Fix, Keep as is, or Defer. Items 1 and 2 are reproducible release issues.
Items 3–11 need a product decision or deployment verification.

RELEASE ISSUES

1. Prevent form data and passwords from entering URLs
   Pages: Public Contact, public reset-password, Admin reset-password.
   Current: Chromium reproduced an early Contact submit sending name, email
   and message in the URL. With JavaScript disabled, both reset pages put
   the new password and confirmation in the URL.
   Expected: Forms submit to the intended POST flow when ready. Before
   JavaScript loads or when it is disabled, submissions must keep all
   personal data and passwords out of URLs. Check other sign-in forms for
   the same browser fallback.
   Verify: Test immediate submit, disabled JavaScript, and normal submit.
   Use dummy data. Check the address bar and network requests. Confirm a
   normal inquiry lands in the inbox and a valid reset updates the password.
   Decision: [ ] Fix before release  [ ] Defer

2. Honor an empty published property list
   Pages: Properties, property detail and other property selectors.
   Current: After all properties were unpublished, the CMS API returned
   zero properties, but a built-in property URL still returned HTTP 200.
   Expected: A successful empty CMS response means zero published properties.
   Keep the behavior for an unavailable API as a separate decision.
   Verify: In a test database, unpublish all properties and their published
   dependents. Check Home, Properties, former property URLs, sitemap,
   Contact and Pay Rent selectors. Former property URLs should return 404.
   Republish one property and confirm only that property returns.
   Decision: [ ] Fix before release  [ ] Defer

   Area: Admin Pages & SEO and public routing.

   Verify based on decision: If new public URLs are supported, create a test

             [ ] Defer
